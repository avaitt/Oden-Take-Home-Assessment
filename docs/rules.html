C09 · Matched signature. Alert when, for the same part, its own sensor (6 h average) is beyond the level the machine reaches only 1% of the time in normal running, and that part's own error code was logged in the last 24 h.
C08 · Drift + any error. Alert when any sensor (6 h average) is far from the machine's normal level (median ± 3.72 robust standard deviations) and any error code was logged in the last 48 h.
C10 · Drift on an aging part. Alert when, for the same part, its sensor (6 h average) is far from normal and the part is older than its typical age since replacement (~31–34 days).

How to read this

  • H (lead time) and W (window): an alert counts if it comes between H + W and H hours before a failure. H = 0, W = 48 means "within the 48 hours before the failure"; the failure hour itself is never scored.
  • The rules are fixed: the same smoothing, threshold scope and level that notebook 04 kept. Changing H, W or the event changes which hours count as normal operation, so each threshold is re-fitted from those hours, and it changes which alerts count. For a single part, C09 and C10 watch only that part's own sensor, error codes and age.
  • Precision: share of alerts followed by a failure within H + W. Coverage: share of failures with at least one alert in their window. F1 balances the two. Lift: how much more often the rule fires before failures than in normal running.
  • At the recommended window (H 12, W 36) the kept C09 scores F1 0.89: 10% of failures get their first alert only in the final 12 hours, which no longer counts. Re-tuned for that window (a slightly more sensitive line, chosen on dev machines), C09 scores 0.94, the same as the F1-best window. This page shows the rules as kept; the write-up, section 11, has both.
  • All numbers are on the 50 holdout machines, which never influenced any choice. Intervals resample whole machines (200 resamples). The data is synthetic and very clean, so treat absolute numbers as optimistic.
